# Story 1.5-10-2: Dead-Letter Queue Handling

**Epic:** 1.5-10 - Operations & Resilience
**Priority:** P2
**Status:** review
**Effort:** 4-6 hours
**Created:** 2025-12-30

---

## User Story

**As the** system,
**I want** failed queue messages to be captured and retried,
**So that** transient failures don't lose user data.

## Acceptance Criteria

### AC1: Retry Logic
- [ ] 3 retries with exponential backoff (1s, 5s, 30s)

### AC2: DLQ Move
- [ ] After 3 failures, move to dead-letter queue
- [ ] Alert: "Message moved to DLQ"
- [ ] Log message metadata

### AC3: Admin Review
- [ ] View: original message, error details, retry count
- [ ] "Replay" to retry processing
- [ ] "Discard" if unrecoverable

### AC4: DLQ Backlog Alert
- [ ] > 100 messages triggers escalation

## Failure Mode Analysis

Queue consumer crashes lose messages - need DLQ.
