# Story 1.5-4-9: Resume Failed Generation

**Epic:** 1.5-4 - Hub-to-Spoke Content Generation
**Priority:** P0
**Status:** review
**Effort:** 4-6 hours
**Created:** 2025-12-30

---

## User Story

**As a** user,
**I want** to resume spoke generation if the workflow fails mid-way,
**So that** I don't lose progress or have to start over.

## Acceptance Criteria

### AC1: Failure Handling
- [ ] Persist state with `last_completed_spoke_index`
- [ ] Set `hubs.status` = "generation_paused"
- [ ] Show error: "Generation paused at 15/25 - tap to resume"

### AC2: Resume UI
- [ ] Banner: "Generation paused at 15/25"
- [ ] "Resume Generation" and "Start Over" buttons
- [ ] Already-generated spokes preserved

### AC3: Resume Logic
- [ ] Continue from last completed spoke
- [ ] Progress: "Resuming... 15/25"
- [ ] Use same generation parameters

### AC4: Start Over
- [ ] Confirm action
- [ ] Delete existing spokes
- [ ] Start fresh from spoke 1

### AC5: Repeated Failures
- [ ] After 3 failures on same spoke, mark as "failed" and skip
- [ ] Notify: "1 spoke couldn't be generated"

## Reverse Engineering Finding

Cloudflare Workflows can fail - need graceful recovery.
