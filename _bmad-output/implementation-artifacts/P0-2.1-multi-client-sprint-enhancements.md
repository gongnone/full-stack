## Story

As an **agency account manager**,
I want **to review content across multiple clients in a single unified sprint**,
so that **I can achieve my 30-minute curation goal without manual context switching**.

## Context

**Problem:** Stories P0-2 and P0-3 assume single-client review sessions. Agency users (Marcus Chen persona) manage 47 clients and need to review 300 pieces across 5 priority clients in one 30-minute sprint.

**User Impact:**
- **Current:** Marcus must manually switch between 5 client contexts, breaking flow and adding 5+ minutes overhead
- **Desired:** Marcus filters by "All Priority Clients" and reviews 47 assets in unified queue with per-client progress tracking

**Business Impact:**
- **Revenue:** Enables $499/mo Agency tier pricing
- **Churn:** Without this, agencies cannot achieve promised 10x efficiency
- **NPS:** Critical for Promoter-range satisfaction

### Technical Architecture

**URL Structure:**
```
Single-client: /app/review?filter=high-confidence&clientId=abc123
Multi-client:  /app/review?filter=high-confidence&clients=abc,def,ghi
```

**localStorage Schema:**
```typescript
// Single-client session
key: "review-session-abc123-top10"
value: {
  index: 12,
  stats: { approved: 8, killed: 4, ... },
  timestamp: 1705762800000
}

// Multi-client session
key: "review-session-multi-abc-def-ghi-top10"
value: {
  index: 24,
  stats: { approved: 15, killed: 9, ... },
  perClientStats: {
    abc: { approved: 8, killed: 2 },
    def: { approved: 5, killed: 4 },
    ghi: { approved: 2, killed: 3 }
  },
  timestamp: 1705762800000
}
```

**tRPC Query Modification:**
```typescript
// Before (single-client only)
input: z.object({
  clientId: z.string(),
  filter: z.enum(['top10', 'needs-review', 'flagged', 'all'])
})

// After (multi-client support)
input: z.object({
  clientId: z.string().optional(),
  clientIds: z.array(z.string()).optional(),
  filter: z.enum(['top10', 'needs-review', 'flagged', 'all'])
}).refine(data => !!data.clientId !== !!data.clientIds, {
  message: "Exactly one of clientId or clientIds must be provided"
})
```

**D1 Query Pattern:**
```sql
-- Single-client (existing)
SELECT * FROM spokes WHERE clientId = ? AND status = 'pending' ORDER BY g7_engagement DESC LIMIT 100;

-- Multi-client (new)
SELECT s.*, c.name AS clientName, c.logoUrl AS clientLogo
FROM spokes s
JOIN clients c ON s.clientId = c.id
WHERE s.clientId IN (?, ?, ?, ?, ?) AND s.status = 'pending'
ORDER BY s.g7_engagement DESC
LIMIT 100;
```

### Performance Considerations

**Multi-Client Query Optimization:**
- Use indexed `WHERE clientId IN (...)` (not 5 separate queries)
- Limit to 100 spokes total (prevent timeout)
- Pre-fetch client metadata in single JOIN query
- Cache client logos in browser localStorage

**Session Storage Scalability:**
- Max 5-10 concurrent sessions per user
- Auto-clear stale sessions (> 1 hour old)
- Per-client stats stored as nested object (not array)
- Total localStorage usage: < 10KB per user
