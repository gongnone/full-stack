## Root Cause Analysis

### Why Weren't These Caught?

1. **UI-Focused Testing**: E2E tests validated UI rendering, not backend logic
2. **Code Review Scope**: Reviews checked that UI correctly renders API responses, not that responses were real
3. **Mock Data Patterns**: Placeholders were structurally correct, so TypeScript and tests passed
4. **Velocity Pressure**: Stories were marked done when UI was complete, deferring backend

### Systemic Issue

The team had an implicit assumption: **"If the UI works and tests pass, the story is done."**

This missed: **"Does the backend actually do what it claims?"**

## Lessons Learned

### 1. "Done" Needs Backend Verification
**Lesson:** Stories with backend components need integration tests that verify real data, not just UI rendering.

**Action:** Add backend integration test requirement to Definition of Done.

### 2. Placeholder Code Should Be Flagged
**Lesson:** `// TODO` and placeholder returns in production code should trigger warnings.

**Action:** Add ESLint rule to flag TODO comments in non-test files.

### 3. Codebase Audits Are Valuable
**Lesson:** The AI-driven codebase audit found 18 issues in minutes that weeks of development missed.

**Action:** Run codebase audits before major milestones (end of epic, pre-production).

### 4. E2E Tests Need Backend Assertions
**Lesson:** Tests that only check UI state miss backend issues.

**Action:** Add API response assertions to E2E tests for critical flows.
